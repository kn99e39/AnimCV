# AnimCV 마스터 플랜

이 문서는 AnimCV의 유일한 선형 실행 계획이다. 세부 실험 결과는 각 보고서에,
기계 판정은 JSON에 남긴다. FBX 생성 성공은 실제 사용 품질의 증명이 아니다.

## 최종 성공 기준

1. 단일 영상의 인물이 해부학적으로 일관된 3D pose를 유지한다.
2. root/torso 방향, hinge, end-effector가 실제 동작과 일치한다.
3. FBX는 FPS·범위·키·부모 변환을 보존하며 Blender 재임포트에서도 일치한다.
4. 정면·측면·회전·보행·가림·다인물 조건의 holdout 품질 게이트를 통과한다.

## 단계와 현황

| 단계 | 목표 | 상태 | 다음 게이트 |
| --- | --- | --- | --- |

| 3 | 시간적 3D 타깃 품질(R1~R6) | 구현 완료, 정확도 미통과 | 외부 GT MPJPE·yaw |
| 4-0 | detector/tracker 입구 | 완료 | tracking success ≥95% |
| 4-1 | confidence 정책 통합 | 완료 | 2D→3D→root threshold 일치 |
| 4-2 | pretrained 3D estimator baseline 비교 | 완료·실패 기준 확보 | 3DHP holdout에서 H36M VideoPose3D 실패 재현 |

## 완료된 품질 보강

- R1 관측 유효성: 저신뢰도 관절을 명시적으로 invalid/interpolated 처리한다.
- R2 고정 길이 복원: raw lift와 보정 lift를 별도 보존한다.
- R3 bend plane: near-straight 관절을 ambiguous로 표시하고 반전을 억제한다.
- R4 root-yaw provenance: shoulder/hip 증거와 hold를 기록한다.
- R5 uncertainty sidecar 및 R6 Blender/시각 감사 artifact를 생성한다.

이 보강은 내부 일관성용이다. MPI-INF-3DHP GT 평가에서 기존 H36M VideoPose3D는
PA-MPJPE 179.25mm, yaw MAE 112.32°로 실패했으므로 게임 제작 품질로 선언하지 않는다.

## 4단계: 3D 정확도 복구

### 4-0. detector/tracker — 완료

RTMDet-tiny + 단일 대상 tracker를 기본 pose 경로로 만들었다. 회전 구간
120프레임에서 tracking success 1.000, no-detection 0을 기록했다.

### 4-1. confidence 정책 — 완료

2D pose JSON이 threshold를 기록하며 lift/root가 별도 override 없이는 이를 상속한다.
0.1 정책의 120프레임 회전 구간은 root까지 완주했다.

### 4-2. pretrained estimator baseline — 실패 기준 확보

H36M VideoPose3D baseline은 MPI-INF-3DHP 회전 구간에서 실패했다. 이 결과는 detector
문제와 3D lifter 문제를 분리하기 위한 비교 기준으로 유지한다.

### 4-3. research-dataset-based supervised 2D→3D baseline and domain evaluation — 설계 완료

웹 연구 데이터셋의 paired 2D/3D annotation을 AnimCV canonical contract로 변환하고,
from-scratch temporal baseline을 build/train/evaluate한다. Human3.6M·MPI-INF-3DHP·AMASS·3DPW의
역할과 코드 공백은 [research dataset assessment](08_RESEARCH_DATASET_ASSESSMENT.md)을 따른다.

**게이트:** 독립 holdout sequence에서 MPJPE, PA-MPJPE, yaw MAE를 측정한다.
초기 후보 기준은 PA-MPJPE ≤80mm, yaw MAE ≤15°, tracker success ≥95%다.

## 이후 순서

`4-3 holdout 통과 → 5 IK/pole/limit → 6 foot/root → 7 FBX visual acceptance → 8 확장 검증`

이 순서를 건너뛰고 리그나 key reduction만 정교하게 만드는 것은 잘못된 3D 동작을
더 정교하게 bake할 뿐이므로 금지한다.
