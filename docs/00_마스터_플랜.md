# AnimCV 마스터 플랜

이 문서는 AnimCV의 유일한 선형 실행 계획이다. 세부 실험 결과는 각 보고서에,
기계 판정은 JSON에 남긴다. FBX 생성 성공은 실제 사용 품질의 증명이 아니다.

## 최종 성공 기준

1. 단일 영상의 인물이 해부학적으로 일관된 3D pose를 유지한다.
2. root/torso 방향, hinge, end-effector가 실제 동작과 일치한다.
3. FBX는 FPS·범위·키·부모 변환을 보존하며 Blender 재임포트에서도 일치한다.
4. 정면·측면·회전·보행·가림·다인물 조건의 holdout 품질 게이트를 통과한다.

| 단계 | 목표 | 상태 | 다음 게이트 |
| --- | --- | --- | --- |

| 3 | 시간적 3D 타깃 품질(R1~R6) | 구현 완료, 정확도 미통과 | 외부 GT MPJPE·yaw |

## 완료된 품질 보강

- R1 관측 유효성: 저신뢰도 관절을 명시적으로 invalid/interpolated 처리한다.
- R2 고정 길이 복원: raw lift와 보정 lift를 별도 보존한다.
- R3 bend plane: near-straight 관절을 ambiguous로 표시하고 반전을 억제한다.
- R4 root-yaw provenance: shoulder/hip 증거와 hold를 기록한다.
- R5 uncertainty sidecar 및 R6 Blender/시각 감사 artifact를 생성한다.

이 보강은 내부 일관성용이다. MPI-INF-3DHP GT 평가에서 기존 H36M VideoPose3D는
PA-MPJPE 179.25mm, yaw MAE 112.32°로 실패했으므로 게임 제작 품질로 선언하지 않는다.

## 4단계: 3D 정확도 복구

### 4-0. detector/tracker — 완료

RTMDet-tiny + 단일 대상 tracker를 기본 pose 경로로 만들었다. 회전 구간
120프레임에서 tracking success 1.000, no-detection 0을 기록했다.

### 4-1. confidence 정책 — 완료

2D pose JSON이 threshold를 기록하며 lift/root가 별도 override 없이는 이를 상속한다.
0.1 정책의 120프레임 회전 구간은 root까지 완주했다.

### 4-2. pretrained estimator baseline — 실패 기준 확보

H36M VideoPose3D baseline은 MPI-INF-3DHP 회전 구간에서 실패했다. 이 결과는 detector
문제와 3D lifter 문제를 분리하기 위한 비교 기준으로 유지한다.

### 4-3. research-dataset-based supervised 2D→3D baseline and domain evaluation — 학습 준비 완료

웹 연구 데이터셋의 paired 2D/3D annotation을 AnimCV canonical contract로 변환하고,
from-scratch temporal baseline을 build/train/evaluate한다. Human3.6M은 이 실행 경로에서
제외한다. MPI-INF-3DHP·3DPW·AMASS의 역할과 코드 공백은
[research dataset assessment](08_RESEARCH_DATASET_ASSESSMENT.md)을 따른다.

2026-08-16 서버 검증에서 MPI-INF-3DHP 106,512프레임, 3DPW train 22,646프레임,
AMASS train 112,898프레임을 합친 242,056프레임/1,046시퀀스 train corpus를 완전
로드했다. validation은 18,612프레임/88시퀀스이며 ID 충돌은 0건이다. RTX 3080 Ti에서
권장 구조(window 81, channels 256, batch 128, AMP)의 1 epoch 실행은 17.58초,
13,766 samples/s, peak VRAM 638.9MiB를 기록했다. 이는 데이터→학습→평가 경로가
실행 가능하다는 증거일 뿐, 1 epoch checkpoint의 최종 품질 합격 증거는 아니다.

다중-view AMASS와 detector-like input augmentation을 적용한 30 epoch direct-mix 기준선은
validation MPJPE 90.78mm, 독립 3DPW test MPJPE 137.54mm, AMASS internal holdout MPJPE
81.59mm를 기록했다. 3DPW test 수치상 게임 제작 품질을 선언할 수 없다. 공통 evaluator는
PA-MPJPE·yaw·hinge/view/action slice를 지원하도록 보강됐지만 이 checkpoint의 v2 holdout
report는 아직 산출하지 않았으므로 최종 게이트는 여전히 판정 불가다. 상세는
[3-source augmented baseline report](09_3SOURCE_AUGMENTED_BASELINE_REPORT.md)를 따른다.

**게이트:** 독립 holdout sequence에서 MPJPE, PA-MPJPE, yaw MAE를 측정한다.
초기 후보 기준은 PA-MPJPE ≤80mm, yaw MAE ≤15°, tracker success ≥95%다.

### 4-3A. 3-source 데이터 활용 순서

1. **MPI-INF-3DHP anchor** — 이미 검증된 paired 2D/3D import로 sequence-disjoint
   train/validation/holdout baseline을 만든다. 이 단계는 좌표축·root-relative contract와
   학습 loop가 실제로 맞는지 판정하는 기준이다.
2. **3DPW 현실 도메인** — 공식 `train`/`validation` split을 별도 artifact로 변환한다.
   MPI-only 모델과 MPI+3DPW 모델을 비교하고, 공식 `test` split은 어떤 학습에도 넣지 않는
   이동 카메라 외부 holdout으로 고정한다.
3. **AMASS synthetic motion** — raw SMPL+H motion을 body model과 virtual camera로 paired
   2D/3D sample로 만든다. 현재 yaw 0°/−45°/+45°, pitch·거리·focal이 다른 세 view와
   학습 시 2D jitter·관절 dropout·confidence noise를 적용한다. 이후,
   AMASS pretrain→MPI/3DPW fine-tune과 direct mix를 각각 비교한다. AMASS만으로 최종
   품질을 판정하지 않는다.
4. **실사용 검증** — 위 holdout을 통과한 단 하나의 후보만 실제 영상→FBX visual regression에
   연결한다.

이 순서는 dataset source·원본 sequence 경계를 모든 split에서 보존한다. 3DPW test와
MPI holdout은 checkpoint 선택·hyperparameter 조정에도 사용하지 않는다.

## 이후 순서

`4-3 holdout 통과 → 5 IK/pole/limit → 6 foot/root → 7 FBX visual acceptance → 8 확장 검증`

이 순서를 건너뛰고 리그나 key reduction만 정교하게 만드는 것은 잘못된 3D 동작을
더 정교하게 bake할 뿐이므로 금지한다.
