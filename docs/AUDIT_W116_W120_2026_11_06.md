## 3. Architectural and evidentiary risks

1. **One real clip, correlated events.** W120's RH1 three variants and DJ_R share the same release events; RH2 has one feasible release. W116 `INPUTS.repo_production_demo_clip` identifies `examples/production_demo/source.mp4` (SHA-256 `0dda8a5f...`) as the W105/W102 authentic source. Consequently, reusing `examples/production_demo/source.mp4` or its 120-frame `constraint_animated_BaseRig.blend` as if it were an independent real video would be invalid. The repository's E2E sample is eight repeated still-image frames; the quality demo is five-frame crowded low-confidence sports footage. Neither is a demonstrated independent positive dynamic source for this world-pin transition mechanism. New real-video evidence requires a genuinely distinct authenticated clip, not a renamed/cropped/re-timed copy.
2. **Synthetic transfer failure.** W120's held-out H_G and other synthetic cases show no material benefit. A method that helps only one release event is not validated for arbitrary edits or motion styles.
3. **Metric/visual mismatch.** A large reduction in a source-relative peak can coexist with nearly unchanged or worse raw animation jumps, bend flips, near-straight frames, source tracking uncertainty and possible contact. The agent's side-by-side proxy render is not a usability study.
4. **Unsettled Production policy.** The human approved automatic bounded, visible out-of-pin editing, **not** permanent elbow-flex, bend-flip, contact, smoothness, default extension width or model-training policy. Diagnostic 1 mm pin, 5-degree near-straight and W119 comparator values must not silently become Production requirements.
5. **Dependency and portability.** Scratch code depends on W116–W119 modules and Main-local Windows paths/artifact stores. It is not yet a reusable Production Editor or independently portable replication package. Original video source remains GT-free; framewise video-person continuity is UNKNOWN; W105 Action 30fps versus 50fps source is unresolved.
6. **Instrument validity.** W116 GB4/GB5, W118 V4 and W119 V6/C3 failed prospectively; W120 explicitly tested budget and class precedence before outcomes. This supports a narrower W120 attribution but does not justify retroactive repair or blanket trust in other unexecuted controls.
7. **No independent execution.** This audit compared GitHub source, tests and Worklog claims, but did not run Blender, inspect Main-local manifests or independently watch the animations. It cannot certify reported numeric quality or human-visible naturalness.

## 4. Product-level assessment and W121 issuance gate

The source-preserving, semantic world-pin and truthful footprint architecture has useful bounded scratch evidence. The *temporal quality* evidence remains context-specific: G1 guides a reachable RH2 release but causes undesirable articulation elsewhere; the flex floor mitigates some straight-arm states and can create flips; no synthetic benefit. Continuing by tuning the same solver on the same clip would risk repeating the diagnostic treadmill rather than improving Animation Authoring.

A meaningful subsequent Batch should test an independent, source-authenticated dynamic animation/user task or another clearly approved authoring capability, with controlled user intent, final Blender output, transparent automatic edit footprint and visual usability evidence. It must not treat W120's two correlated release events as multiple independent clips, implement a new constraint type, train a Generator, change Production UI/schema or choose a permanent joint-quality threshold without human authorization.

**Audit complete. No W121 prompt is issued by this audit document.** Preserve W120's official B and all earlier CASEs. If no new independent evidence source or authorized bounded task is available, HOLD rather than manufacture positive controls or repurpose invalid low-confidence examples as success evidence.
