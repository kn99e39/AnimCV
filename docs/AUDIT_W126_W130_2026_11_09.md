## Cross-cutting architecture / code findings

1. **Product ownership remains separated in the inspected diff.** `Architecture_v3_FramePose.md` remains normative for perception; v2 retains downstream contracts; experimental Blender/FBX and MotionBricks paths are opt-in. W129 does not silently alter Production CLI/GUI, FramePose, MotionGraph, retargeter or default exporter. W130 changes only a preflight script. Source GT-free hypotheses, synthetic body fill, native-time identity and user hard pins remain explicitly distinguishable.
2. **Source quality is the dominant unsolved product problem.** W129's real model inference and representation round-trip demonstrate *execution feasibility*, not better motion. The source-derived S1 world-space discontinuity includes parent/object motion which a left-arm-only proposal cannot repair. The learned result deviated more from the reference action than simple interpolation, including an independent negative S3 transfer. No evidence supports automatic Generator promotion or learned trust.
3. **Quality evidence is weaker than the mechanical gates.** The W129 A/B/C native-30-fps video is reportedly saved only under local scratch `C:/Users/dna10/animcv-w129/results`; it is not committed. Reviewers cannot independently inspect or replay it from GitHub. The Agent judged contact sheets, not native-rate playback; no human animator review. Unit tests partly use a synthetic SOMA-like skeleton and mock FK; Agent-run real Blender controls are separate and should not be conflated.
4. **License/access preflight must precede any heavyweight model experiment.** W130 prevented a ~20 GB download and unlicensed local run. A public ungated checkpoint and MIT inference code are not enough to infer rights to weights or their upstream derivatives. The currently inspected alternatives do **not** yet provide a verified, compatible, clearly permitted pretrained source-conditioned model with a demonstrated S1/30-fps partial-body contract: MotionFix's MIT `LICENSE` conflicts with its README's noncommercial-research wording and checkpoint terms are not established; MotionLab and ProjFlow have no verified repository-level licensing grant for the distributed weights. Do not turn this uncertainty into a presumed permission.
5. **Central documentation freshness is incomplete.** `PRODUCT_VISION.md` §4.1 still describes W123 as issued/not complete, although W123–W130 are complete; `docs/README.md` latest-status note stops at W128. These are *status drift*, not permission for the Reviewer to change normative contracts. A separately authorized implementation/documentation task should reconcile living status while preserving the actual Worklog verdicts.
6. **Review boundary.** This audit does not establish cryptographic resistance to a consistent hostile rewrite, all Blender C-level file access, general FBX compatibility, production-quality generative motion, licensed checkpoint rights, or physical locale. It does not retroactively upgrade or downgrade any official CASE. The approved narrow local Worker clean merge for concurrent canonical-document edits is outside the reviewed Batch source changes and is **not** treated as a violation.
