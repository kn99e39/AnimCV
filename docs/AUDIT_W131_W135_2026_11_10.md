## Cross-batch architecture and implementation findings

1. **Ownership and branch integrity.** The compared files add scratch modules, runners, tests, declarations, Worklogs and the single current Batch instruction. No `scripts/batch_automation.py` edit, Production CLI/GUI, MotionGraph, default Blender/FBX exporter, FramePose normative contract or branch-policy change appears in the diff. The human-authorized narrow concurrent-publication clean merge remains permitted and is not a reason for HOLD.
2. **Mechanical correctness is not animation utility.** W131 and W135 establish actual Blender Action construction and pin/footprint checks. W135 D and E share identical wrist trajectory, flexion and timing by design, so D cannot correct errors already present in B. The Agent reports world shoulder steps up to **244 mm/frame** from immutable parent/object tracks. That source-derived popping is **outside** the authorized left-arm edit domain and cannot be silently modified by a follow-on batch.
3. **Generator evidence is negative or blocked, not a Production foundation.** W131's real CondMDI result is inferior to interpolation on S1; W132 isolates one failure mechanism; W133 and W134 never execute their checkpoints; W135 isolates a separable MotionBricks elbow signal but not a perceptual benefit. None establishes natural, source-faithful, editable animation better than the frozen simple baseline on real S1. Do not promote scratch representations, trained reliability, automatic edit authority or a new schema.
4. **Model-derived is not necessarily model-learned.** W135's D−E difference identifies the transplanted C prior's effect under a matched solver. It does **not** isolate the contribution of learned motion from W129's endpoint correction or from coordinate/rig projection. W135 itself records 31–54° W129 arm correction as a possible confound. The a-priori reference axis had to be replaced by an outcome-blind input-margin rule before D/E; the resulting decomposition is reference-dependent.
5. **Rights and execution must be scoped per artifact.** Code license, weight license, training-data conditions, third-party body assets, text-encoder access and generated-output rights are distinct. W135's Agent fetched a current NVIDIA Open Model Agreement and classified local output evaluation as permitted, but did not archive the version in force at W129's download. W131's checkpoint-label interpretation remains disputed by W133's documentary evidence. Neither uncertainty warrants rewriting frozen CASEs; it does prohibit an unexamined deployment claim.
6. **Perceptual evidence gap remains material.** W135 produced a native-30-fps file but the Agent reviewed only unblinded stills, did not open the exit sheet, and did not perceive the video at native rate. W131 likewise lacked human/native-rate assessment. Stored scratch media are not accessible through the repository. A mechanical PASS, a generated video file, and synthetic unit tests are not independent human animation-quality validation.
7. **Living-document status drift.** `PRODUCT_VISION.md` §4.1 and `Architecture_v3_FramePose.md` still refer to W123 as issued, while official Worklogs now reach W135. This is a dated-status inconsistency, **not** authority for this reviewer to edit normative documents. Any authorized later Batch that reaches a genuine milestone should reconcile canonical status with precise evidence while preserving architecture precedence and old Worklogs.
