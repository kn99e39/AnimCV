PURPOSE

W120 was officially CASE B — PARTIAL / CONTEXT-SPECIFIC SUPPORT.
Under matched frozen 2x2 controls (G0F0, G0F1, G1F0, G1F1), a world-space
wrist guide improved one reachable RH2 release event; RH1 benefited only

primary boundary metric. New bend flips, near-straight arm poses and
synthetic failures remained.

RH1, RH2 and DJ_R are correlated events of the SAME GT-free source clip.
The repository production_demo/source.mp4 is the SAME W102/W105 source,

dynamic sources.

The W116–W120 cumulative audit at
docs/AUDIT_W116_W120_2026_11_06.md is COMPLETE.
Its conclusion is scope/history PASS WITH LIMITS, NOT Animation Quality PASS.

Further experiments on the same single source or post-hoc solver tuning
would not resolve whether the mechanism is useful beyond that source.
The user chose independent real-video testing to address this uncertainty.

CENTRAL INTENT

With the full W120 guide/flex-floor mechanisms, rig, numerical policies,
authorization contract and evaluation criteria held fixed, do genuinely
independent dynamic video-derived animation states exhibit defensible
world-pin transition benefits under controlled user-edit tasks?

In which observed conditions does the guide transfer, fail, become
unreachable, create undesirable articulation, or merely optimize a metric
without improving visually meaningful animation continuity?

Test the transferability of the EXISTING mechanism, not the ability to
tune a new method to a selected clip.

REQUIRED EVIDENCE — PART 1
INDEPENDENT SOURCE ACQUISITION AND AUTHENTICATION

The human approved searching for and preparing independent real motion
video for this Batch; the footage itself was NOT supplied in this chat.

Before assessing solver outcomes, inspect legitimately accessible candidate
sources, including public/permissively licensed openly usable video when
network access is available. Verify source license/permission and retain
URL/publisher, access date, original bytes, SHA-256 and source metadata.
Do not bypass access controls, use restricted downloads, or introduce
unlicensed private footage. If local independently sourced video is already
available, verify its actual provenance and legitimate use instead of
assuming a file name establishes independence.

Use an objective pre-selection suitability protocol:
- genuine changing video footage with discernible human arm motion;
- an identified usable subject and sufficient continuous limb observation;
- manageable occlusion and sufficient temporal coverage for one
  nontrivial world-wrist pin and adjacent transition evaluation;
- frozen perception/rig path can process it without Production changes;
- no requirement to use privileged GT at runtime.

Seek at least TWO independent original dynamic sources where feasible,
preferably different motions/subjects/camera contexts. A single independent
source is a legitimate bounded transfer test, but NOT multi-clip
generalization. Log every screened candidate and rejection rationale.

Explicit duplicate/derivative exclusions:
- W102/W105 source SHA 0dda8a5f...;
- examples/production_demo/source.mp4 (same source);
- W116–W120 original video, crops, re-encodes, time shifts and edits;
- repeated still-image sequences or mere screenshots;
- previous benchmark images repackaged as a supposedly independent
  video from a separate real capture;
- synthetic/GT projections labelled as real observations.

Compare media duration, frame fingerprints, matched visual subsequences,
and source/publisher metadata to detect duplicates, not just file SHA.
Store originals outside the repository. Publish provenance, exact paths,
hashes and compact checks, not unnecessary copyrighted video bytes.

Do not allow the visible success/failure of a solver run to decide which

CONTROLLED DECISION AND EVIDENCE LEVELS

Before candidate execution, declare precise non-vacuous A/B/C/D gates
and a distinct DATA BLOCKED status.

CASE A — BOUNDED CROSS-SOURCE SUPPORT:
Authentic independent dynamic source(s), valid frozen source-to-rig
pipeline, rigorous matched controls, safety/rollback/visibility checks,
and reproducible meaningful guide improvement on predeclared
new-video episodes without critical new hard-pin, articulation or
collateral failures. A is bounded, not universal generalization.
If only one new clip is available, say ONE-SOURCE TRANSFER, not
multi-clip generalization.

CASE B — PARTIAL / CONTEXT-SPECIFIC:
Valid transfer tests show limited successes but poor coverage,
mixed quality, significant side effects or no consistent
improvement across independent sources/episodes. Attribute each
mechanism and limitation separately.

CASE C — NOT SUPPORTED:
Valid independent transfer evidence rejects the W120 mechanism's
material utility or safety contract on the declared populations,
even though frozen source/rig controls are valid.

CASE D — INVALID:
Input provenance, fairness, evaluator, negative controls, source
association or predeclared numerical/test contracts are unreliable,
so meaningful interpretation is impossible.

DATA BLOCKED — NO CASE:
A genuinely independent usable dynamic input could not be obtained,
legitimately used, authenticated or passed frozen ingestion preflight.
Report exactly what is unavailable; do not turn this into CASE A/B/C
or a code-only validation success.

D precedes A/B/C when a test was attempted under invalid controls.
DATA BLOCKED takes precedence when the independent test population
could never be established.

Do not relax gates or choose a new clip following observations.
