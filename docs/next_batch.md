# BATCH 112 — FBX Within-Property Interpolation Recoverability Boundary (Evidence Only)

## DIRECTION
Continue the user's explicit decision to pursue FBX compatibility recovery. Test the architectural limit exposed by W110/W111: Blender's FBX importer collapses FBX axis curves into property-level imported Action curves. This is a bounded diagnostic of whether interpolation-only post-import recovery remains sufficient when interpolation differs within one transform property. Do not deploy or patch a product path.

## PURPOSE
W111 completed CASE A (bounded) for semantic repeatability under exporter UID, ordering and path variation; it did not repair stock FBX behavior. W110 remains CASE D under its frozen repeat gate. Both used uniform interpolation within each FBX transform-property group; the real Actions were rotation-only and entirely held, while the mixed synthetic control separated held and smooth motion across different bones. W110 explicitly leaves within-property mixed axes or key intervals unresolved. Determine whether that exclusion is merely a conservative adapter rule or a representational loss imposed by Blender's matrix-baked import. An unsupported case must not be silently treated as a recoverable case.

## CENTRAL INTENT
When FBX AnimationCurves for the SAME transform property carry different interpolation semantics across axes or key intervals, can the unchanged Blender 5.1 imported Action recover the source's evaluated rig motion through interpolation-only edits informed by FBX metadata, or does the importer-induced curve representation make that impossible without changing keys, transforms, or the import/export boundary?
