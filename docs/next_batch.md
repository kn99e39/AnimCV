# BATCH 109 — FBX Importer CONSTANT-Flag Behavioral Ownership (Evidence Only)

## CURRENT ASSESSMENT — SUCCESS / FAILURE / UNCERTAINTY

**Human Assessment**
- **SUCCESS:** W108 is committed and COMPLETE, CASE A. All three existing BaseRig Actions are CONSTANT in Blender, but V0/V1 FBX curves serialize LINEAR (`KeyAttrFlags=0x6104`); independent and Blender-add-on FBX parsers agree. On copied V1 imported Actions, changing **only** F-curve interpolation to CONSTANT lowers subframe world-coordinate error from 0.594 / 1.071 / 0.433 m to 0.95 / 1.31 / 1.66 µm. A synthetic held-step control improves, while a genuinely smooth LINEAR control is harmed. Integer-frame data and source Actions remain unchanged.
- **FAILURE:** Neither the production V0 exporter nor the scratch W107 V1 no-simplification export preserves the original held temporal function through Blender's FBX round trip. W107 V1's larger files/keys, W106 frame range, multi-take export, and native 50 fps vs scene 30 fps are separate unresolved issues. W108 P2 is a diagnostic, **not** a deployable fix.
- **UNCERTAINTY:** The Blender 5.1.0 FBX importer source appears to ignore `KeyAttrFlags` and force LINEAR, but no **behavioral import of a correctly CONSTANT-flagged FBX** has been performed. It remains unknown whether an export-side interpolation correction alone could ever restore the hold in this particular Blender-to-Blender path. Main-local W106–W108 binaries and test reports were not independently replayed by this reviewer.
- **ALTERNATIVE EXPLANATIONS:** Incorrect CONSTANT-standard versus CONSTANT-next encoding, malformed scratch FBX, altered key times/values or take assignment, mismatched slot/Action, importer-side resampling, timebase/scene setting, or different semantics between synthetic and real Actions.

**Why this Batch matters:** W108 located the first loss at export serialization; it did **not** establish the independent import boundary behavior. If the importer discards correctly encoded CONSTANT flags, an exporter-only change cannot satisfy the Blender round-trip contract. One bounded, falsifiable, scratch-only import experiment can resolve that architectural dependency **before** any user-owned export/import policy decision. Do not turn this into a sequence of implementation patches.
